# Meet Alex

Alex is studying a course with a programming component, helps a student society,
and works part-time. Today is busy, not exceptional.

The group is building a [student survival hub](../project/brief.md). Alex owns the
study planner. A teammate is writing campus guidance. Another is checking the
launch budget. Everything must fit together before the group can publish.

![Alex and a Copilot companion present the student survival hub, showing how coding and non-coding contributions come together in a MkDocs site with a JavaScript study planner, published through GitHub Pages.](../assets/Neon%20Student%20Survival%20Workshop.png)

You play Alex for the coding path. On the alternative path, play a teammate
contributing to the same outcome. No real student identity or personal data is needed.

## How each scene works

1. Read the moment and name the friction.
2. Attempt the task briefly before asking Copilot.
3. Supply context, a goal, constraints, and a way to check the result.
4. Inspect the response and make a decision yourself.
5. Save a small artifact another person could use.

Use this prompt pattern throughout:

> Here is the context and my attempt. Help me achieve this specific goal.
> Respect these constraints. Identify assumptions and missing information.
> Explain how I can verify the result. Ask before changing files.

You do not need to type prompts exactly as written. Adapt them to your task and
available client. Attach or explicitly supply the named files; Copilot does not
automatically see private chats, lectures, calendars, or every repository file.
